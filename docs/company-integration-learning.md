# 企业资料前端：分步实现与学习说明

本轮将企业资料原型接入现有 Vue 3、Element Plus、Vue Router 工程。
按接口基础、管理展示、完整编辑、文件管理、审核闭环、求职者主页六步组织代码。
没有修改后端业务代码，没有提交或推送 Git。

## 第一步：把接口契约集中起来

入口文件：

- `src/api/company.js`：本人资料、预览、公开主页、照片、资质和企业审核历史。
- `src/api/companyReview.js`：管理员工商审核、材料审核、审核原件。
- `src/constants/company.js`：与后端一致的枚举代码、中文文案、字段定义及文件限制。
- `src/utils/company.js`：表单副本、保存字段白名单、值归一化和组合校验。

API 仍返回 Axios response，页面读取 `response.data.data`，分页读取其中的 `items/total`。
不改变其它模块已经采用的响应结构。展示用中文标签，提交用英文枚举代码，例如 SOFTWARE。

`COMPANY_SECTIONS` 定义四组共 29 个业务字段，包含 key、label、类型、长度和必填标记。
表单渲染、字段白名单和前端校验使用同一份定义，减少三套列表各自修改产生的遗漏。
profileVersion 是并发参数，单独保留；id、归属、审核状态、Logo 不属于资料保存字段。

**面试问题：为什么不直接把 GET 返回对象提交回去？**

GET 的 VO 含系统状态、版本和派生信息，保存 DTO 只接收允许编辑的字段。
前端白名单减少误传；真正的安全边界仍是后端 DTO、Service 权限及字段赋值规则。

## 第二步：组合管理页，分别表达三种状态

入口 `src/views/company/CompanyInfo.vue` 负责请求、加载状态和组件协调：

```text
CompanyInfo
  ├─ CompanyTrust           可信档案与真实核验标记
  ├─ CompanyDetails         公司概况、工商信息、制度福利、产品团队
  ├─ CompanyPreviewCard     已保存资料的侧栏预览
  ├─ CompanyFileManager     上传、下载、删除或移除
  ├─ CompanyReviewHistory   企业自己的审核反馈
  └─ CompanyEditor          编辑副本与完整保存
```

管理数据来自 GET /company，预览数据来自 GET /company/preview。
status 只表示企业准入；registrationVerified 表示当前工商版本核验；
businessLicenseVerified 表示是否存在有效、已通过的营业执照。
这些结果由后端计算，前端负责映射文案，不自行根据“上传成功”推导“审核通过”。

加载失败展示重试，旧资料缺失展示待完善，没有照片、材料、历史或岗位有空态。
原型的示例照片、默认已核验、固定岗位都没有作为业务数据写入页面。

**面试问题：为什么状态不在前端重新计算？**

核验涉及版本、审核结果和材料移除状态，后端拥有完整数据及事务边界。
前端重新猜测会造成不同页面口径不一致。

## 第三步：四组编辑，保存一份完整 DTO

入口 `src/components/company/CompanyEditor.vue`。
旧 `/layout/company/edit` 入口保留，但统一转入档案页编辑弹窗，避免维护两套保存逻辑。

1. 打开时调用 createCompanyForm，创建独立副本；benefits 也复制数组。
2. 点击模块编辑只改变当前标签，不删掉其它标签的数据。
3. validateCompanyForm 检查必填、长度、枚举、官网、信用代码、成立日期及字段组合。
4. 错误定位到第一个不合法字段所属标签。
5. updateCompany 内部调用 toCompanySavePayload，只发送业务白名单和读取时的 profileVersion。
6. 空白字符串归一为 null，benefits=[] 表示清空；保留未在当前标签编辑的其它字段。
7. 保存成功关闭弹窗，重新读取管理资料、公开预览和审核历史。
8. 失败保留用户输入；取消、离开路由或刷新页面时提示未保存修改。

**完整保存为何需要保留其它字段？**

后端 PUT 是完整替换，可选字段省略或 null 都表示清空。
它不等于只更新传入字段的 PATCH。分组是界面组织方式，不改变后端契约。

**乐观锁如何贯穿前后端？**

```text
GET 读取 profileVersion
 → 编辑期间持有该版本
 → PUT 携带原版本
 → 后端 WHERE 条件匹配版本并递增
 → 影响行数不为 1 则冲突，事务不允许覆盖别人的更新
```

后端主表、福利与工商快照在同一事务中保存。
前端不能收到冲突后偷偷取新版本自动重试，否则仍会覆盖他人的业务内容。
本实现保留输入，让用户重新读取并核对修改。

## 第四步：文件与 JSON 是两种响应

入口 `CompanyFileManager.vue`、`CompanyPhoto.vue`、`src/utils/companyFile.js`。

- FormData 上传，不手工设置 multipart boundary。
- 图片仅 JPG/PNG，每张 3 MiB，最多 6 张；资质支持 JPG/PNG/PDF，每份 10 MiB。
- 选择资质类型后上传，新材料显示真实待审状态。
- 前端检查用于及时反馈，后端仍校验实际内容、大小、数量与归属。
- 图片请求通过既有 Axios 发送 Bearer，不将 Token 放在 URL。
- 图片 Blob 转成对象 URL；组件销毁或切换照片时 revokeObjectURL。
- AbortController 取消旧图片请求，避免旧响应覆盖新照片或产生未回收 URL。
- 文件读取即使 HTTP 200，也可能返回 code=500 的 JSON Blob；readCompanyFile 根据 Content-Type 识别并拒绝。
- HTTP 失败中的 JSON Blob 由 fileError 解析；401 仍沿用原有登录过期处理。
- 照片删除、材料移除后重读列表和核验标记，不仅删掉页面上的一行。

**面试追问：为什么不能直接 `<img src="后端路径">`？**

普通图片标签不会自动附加存储在 localStorage 的 Bearer 令牌。
因此由带鉴权的请求获取 Blob，再使用本地对象 URL 展示。
对象 URL 持有资源引用，不释放可能导致内存逐步增长。

## 第五步：审核操作与历史证据分开

企业侧 `CompanyReviewHistory.vue` 分开查询工商与材料反馈，展示版本、原因、时间及移除标记。
管理员侧 `AdminCompanyReviews.vue` 提供两个队列、筛选、分页、提交快照、原件下载与审批。

工商决定携带详情中的 registrationVersion，材料决定不传工商版本。
驳回必须填写原因，最多 500 字。提交前确认、提交中禁用重复操作。
后台拒绝旧记录或竞态审批时，重新读取详情并保留意见；不在前端先把待审改成通过。

reviewable 只用于界面是否展示审批按钮，不是权限控制。
后端仍检查管理员角色、记录状态、工商版本、材料移除及锁定后的当前数据。
材料移除后企业不能再下载，但管理员仍可下载历史原件；已处理记录不能重复审批。
原有企业准入管理页继续保留，入口与两类核验队列明确分开。

**面试问题：为什么企业删掉材料，平台还保留原件？**

企业移除改变的是当前有效材料，历史审批依据仍需追溯。
所以材料有效性、审核决定和证据保留是不同概念。

## 第六步：共享展示组件，分别执行权限对应的查询

- 企业本人预览使用 GET /company/preview；岗位预览复用企业列表并筛选 ACTIVE。
- 求职者路由 `/layout/company/:id/profile` 使用公开主页与企业在招岗位接口。
- CompanyPublicContent 复用展示结构，不决定当前账号应该调用哪一套管理接口。
- 公开岗位分页参数是 pageSize，企业岗位列表参数是 size，分别封装。
- 岗位详情用已有 companyId 提供企业主页入口；企业主页岗位卡片回到已有岗位详情。
- 切换企业 ID 或翻页时，用请求序号忽略过期响应，防止旧请求回写当前页面。
- 路由 meta 限制入口，后端角色与企业可见性检查是最终防线。

**面试问题：复用组件为什么不意味着复用所有接口？**

相同外观可以共用组件，但企业与求职者拥有不同数据范围和操作权限。
父页面按身份取数，子组件仅展示约定字段，避免把管理视图当成公开视图。

## 原型对齐与本期边界

已按原型核对双栏比例、企业头部、可信档案五行、模块顺序、四组弹窗、侧栏预览、完整主页与窄屏布局。
沿用现有应用导航和 Element Plus 控件；新增审核历史和管理员审核页面用于真实业务闭环。
原型的“实时预览”改为“已保存资料预览”，不把未保存内容冒充后端数据。
真实缺失数据以空态呈现，不保留原型示例认证或固定照片。

Logo 只复用现有读取；本阶段没有 Logo 专用上传、照片标题编辑或手动排序接口。
照片顺序采用后端 sortOrder/id，界面不提供无法持久化的拖拽排序。
文件存储仍是后端现有单实例私有目录。没有新增工商外部查询、企业注销、对象存储等功能。
